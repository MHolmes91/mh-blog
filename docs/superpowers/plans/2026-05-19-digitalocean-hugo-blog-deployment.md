# DigitalOcean Hugo Blog Deployment Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Create `MHolmes91/mh-blog` as a separate Hugo production blog that consumes `github.com/MHolmes91/mh-blog-theme` as a Hugo Module and deploys to DigitalOcean App Platform as a static site.

**Architecture:** The new blog repository owns content, site config, Node build dependencies, and the DigitalOcean app spec. This theme repository remains a separate dependency imported through Hugo Modules. DigitalOcean builds the blog from GitHub, runs `npm ci && hugo --gc --minify`, and serves `public` as a static site.

**Tech Stack:** Hugo extended `>=0.146.0`, Hugo Modules, Go modules, npm, Alpine.js, Tailwind CSS via Hugo's `css.TailwindCSS`, GitHub, DigitalOcean App Platform static sites.

- [ ] **Step 2: Capture the app ID and default ingress URL**

Run from `/Users/mark/Repositories/mh-blog` after Step 1 succeeds:

```sh

APP_URL="https://$APP_HOST"
```

Expected: shell variables are set for subsequent verification commands.

- [ ] **Step 3: If `doctl` is unavailable, create the app with the DigitalOcean API**

Run from `/Users/mark/Repositories/mh-blog` only if Step 1 cannot be used and `DIGITALOCEAN_TOKEN` is set:

```sh
curl -X POST \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $DIGITALOCEAN_TOKEN" \
  -d "$(ruby -ryaml -rjson -e 'puts({spec: YAML.load_file(".do/app.yaml")}.to_json)')" \
  https://api.digitalocean.com/v2/apps
```

Expected: API response includes an app object with an `id`.

- [ ] **Step 4: Check deployment status**

Run from `/Users/mark/Repositories/mh-blog` after setting `APP_ID`:

```sh
doctl apps get "$APP_ID" --format ID,DefaultIngress,ActiveDeployment.Progress.SuccessSteps,ActiveDeployment.Progress.ErrorSteps
```

Expected: deployment progresses without error steps.
